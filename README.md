# Imeichanger

Android-приложение для смены IMEI на устройствах MediaTek. Работает через скрытый
системный сервис `phoneEx`, которому передаёт AT-команды для модема.

Подробно про AT-команды и binder-протокол: [docs/at-commands.md](docs/at-commands.md).

## Что умеет

- Показывает текущий IMEI для SIM 1 и SIM 2.
- **Ручная смена:** ввод 15 цифр с проверкой длины и контрольной цифры (алгоритм Луна).
- **Автоматическая смена:** выбор производителя и модели из каталога TAC, IMEI
  генерируется как `TAC + 6 случайных цифр + контрольная цифра`.
- Перед записью показывает диалог подтверждения. При первой смене на слоте
  предупреждает, что текущий IMEI будет сохранён как заводской.
- **Reset** возвращает заводской IMEI.
- История смен по каждому слоту.

## Требования

- Устройство на MediaTek с сервисом `phoneEx` (`com.mediatek.internal.telephony.IMtkTelephonyEx`).
- Разрешение `MODIFY_PHONE_STATE`. Оно системное, поэтому APK должен быть подписан
  платформенным ключом прошивки устройства. Без этого вызовы `phoneEx` будут отклонены.
- Android 12+ (`minSdk 31`).

## Сборка

```bash
./gradlew assembleDebug   # APK: app/build/outputs/apk/debug/
./gradlew test            # unit-тесты (IMEI, разбор CSV, группировка каталога)
```

Для работы без устройства с `phoneEx` (например, на эмуляторе) замените в
`MainViewModel.Factory` `PhoneExImeiRepository` на `StubImeiRepository`.

### Как идут вызовы

```
MainScreen ──события──▶ MainViewModel ──▶ PhoneExImeiRepository ──▶ PhoneExClient ──▶ phoneEx ──▶ модем
     ▲                       │                     │
     └──── MainUiState ◀─────┘                     └──▶ ImeiStorage (imei_state.json)
```

- `MainViewModel` держит состояние экрана: выбранный слот, открытый диалог,
  сообщение. Ещё он проверяет ручной ввод и генерирует IMEI из TAC. `uiState`
  собирается через `combine` из локального состояния и потоков репозитория.
- `PhoneExImeiRepository` выполняет каждую операцию (чтение при старте, смена,
  reset) как одну `modemSession`: на `Dispatchers.IO` и под общим `Mutex`. Поэтому
  последовательности команд никогда не перемешиваются. Пока сессия идёт или ждёт
  своей очереди, `isBusy == true`, и экран перекрыт окном загрузки.

## Заводской IMEI и история

Модем не хранит отдельной копии заводского IMEI. «Заводским» считается **первый
IMEI, который приложение прочитало в слоте**. Он сохраняется вместе с историей в
`filesDir/imei_state.json`:

```json
{"originalImeis": {"SIM1": "356938035643809", "SIM2": "356938035643817"},
 "history": [{"slot": "SIM1", "timestamp": 1760000000000,
              "oldImei": "356938035643809", "newImei": "490154203237518"}]}
```

Файл переживает перезапуск, обновление приложения и очистку кеша. **Не переживает**
«Очистить данные», переустановку и сброс к заводским настройкам. Тогда заводским
станет текущий IMEI, поэтому при первой смене на слоте приложение просит сверить
его с коробкой или `*#06#`.

## Каталог устройств

Каталог читается из всех файлов `app/src/main/assets/tac/*.csv`. Большой каталог
можно разбить на несколько файлов.

Формат строки: `brand,tac,specs,model`, например:

```
brand,tac,specs,model
10.OR,91161200,10.OR,10.OR D
```

- Разделитель `,` или `;` определяется автоматически, кавычки поддерживаются.
- Строки без корректного TAC пропускаются, в том числе заголовок.
- TAC короче 8 цифр дополняется нулями слева. Excel любит обрезать ведущие нули.
- Если `model` пустой, берётся `specs`, если пуст и он, берётся `brand`.
- Бренды и модели группируются без учёта регистра. Строки с одной моделью и
  разными TAC объединяются, при выборе модели берётся случайный TAC из них.
- Каталог загружается целиком в память при первом открытии выбора устройства.
