# AT-команды и протокол phoneEx

Как приложение общается с модемом MediaTek. Код: `phoneex/PhoneEx.kt` и
`data/PhoneExImeiRepository.kt`.

## Транспорт: binder-сервис `phoneEx`

AT-команды отправляются не через последовательный порт, а через скрытый сервис
`phoneEx`. Его binder берётся рефлексией через `android.os.ServiceManager.getService("phoneEx")`.

**Запрос** — транзакция `43` (`sendAtCmd`), interface token
`com.mediatek.internal.telephony.IMtkTelephonyEx`:

| Поле | Тип | Значение |
|---|---|---|
| slot | `int` | всегда `0` (см. ниже) |
| token | `long` | `0` |
| atCmd | `String` | AT-команда |
| callback | `IBinder` | наш `IOemHookCallback` |

После `transact` читается `reply.readException()`. Сервис только принимает команду,
ответ модема приходит **позже и асинхронно** в колбэк.

**Колбэк** `IOemHookCallback`, дескриптор `com.mediatek.telephony.IOemHookCallback`:

| Транзакция | Метод | Аргументы |
|---|---|---|
| `FIRST_CALL_TRANSACTION + 0` | `onAtCmdResp` | `int slot, long token, String response` |
| `FIRST_CALL_TRANSACTION + 1` | `onAtUrcInd` | `int slot, String urc` |
| `FIRST_CALL_TRANSACTION + 2` | `onError` | `String error` |

Перед первой командой `PhoneExIntrospection.probe()` пытается прочитать настоящий
дескриптор и коды транзакций из классов фреймворка. Если не получилось, используются
значения из таблицы выше (`CallbackLayout.FALLBACK`).

## Слоты и тип EGMR

Какой IMEI читать или писать, задаёт **тип** в команде `EGMR`, а не binder-слот.
Модем binder-слот игнорирует, поэтому все команды уходят на слот `0`.

| SIM в приложении | Тип EGMR |
|---|---|
| SIM 1 (IMEI1) | `7` |
| SIM 2 (IMEI2) | `10` |

## Чтение IMEI

```
AT+EGMR=0,<type>
```

- `0` означает режим чтения. Пример: `AT+EGMR=0,7` читает IMEI1.
- Ответ выглядит как `+EGMR: "353332990071343"`. Приложение берёт первую группу из
  15 цифр, кавычки и префикс не важны.
- Ответ ждём до 5 секунд (`RESPONSE_TIMEOUT_MS`). Если он не пришёл, IMEI считается
  неизвестным.

## Запись IMEI

Последовательность, проверенная на устройстве:

| Шаг | Команда | Пауза после | Зачем |
|---|---|---|---|
| 1 | `AT+CFUN=0` | 1 с | выключить радио |
| 2 | `AT+EGMR=1,<type>,"<imei>"` | 1 с | записать IMEI (`1` означает режим записи) |
| 3 | `AT+CFUN=1,1` | 3 с | включить радио с перезагрузкой модема |
| 4 | `AT+EGMR=0,<type>` | — | прочитать IMEI обратно для проверки |

Пример для SIM 2:

```
AT+CFUN=0
AT+EGMR=1,10,"490154203237518"
AT+CFUN=1,1
AT+EGMR=0,10
```

- Шаги 1–3 отправляются без ожидания ответа, ответы только пишутся в лог.
- Шаги 1–3 нельзя прервать (`NonCancellable`): если остановиться после
  `CFUN=0`, радио останется выключенным.
- Вся последовательность выполняется под общим `Mutex`, чтобы другие команды не
  вклинились между записью и проверкой.
- Если проверочное чтение не удалось, в состояние приложения пишется отправленный
  IMEI. Это известное ограничение: успех записи сейчас не подтверждается.

## Отладка

Весь обмен с `phoneEx` пишется в лог с тегом `imei_phoneex`:

```bash
adb logcat -s imei_phoneex
```

Там видно каждую отправленную команду, сырые ответы модема и результат probe колбэка.
Если probe не может прочитать классы фреймворка, на тестовом устройстве можно
ослабить ограничения скрытых API:

```bash
adb shell settings put global hidden_api_policy 1
```
